# Known limitations and demo readiness

Jom! is a hackathon MVP. All pilot graph attributes are synthetic; no real-world safe or universally accessible route is promised. The accepted native schematic renders actual API geometry projected into local canvas coordinates. The separate geographic map-provider spike remains unresolved. No GPS, geocoding, turn-by-turn guidance, live closures/elevator feed or departure-time simulation is implemented.

The demo data-quality assessment clock is fixed. Missing verification dates remain unknown. Safer-at-Night confidence is capped for incomplete accessibility; Step-Free excludes unknown critical access. A source's synthetic venue verification does not verify a real facility. Covered/shaded and ramp/elevator preferences are visibly saved-only; Custom/age-friendly profiles are deferred. Existing supported needs can change the baseline demo route times.

Supabase requires externally provisioned public configuration, anonymous sign-ins and both migrations. Guest recovery/account linking is absent. Public photos must be non-personal. Published community reads are public; ownership and privileged verification are enforced by RLS/triggers. A report is not a graph update. Feed/history fetch the latest 100 entries; pagination, moderation, contribution quotas/CAPTCHA, operational verification, orphan-image cleanup and guest retention are production work. Local mode is an explicit separate dataset, not automatic fallback or remote sync. Uncertain saves after connectivity loss need a feed/history check before retry.

Demo setup is non-destructive and manifest-scoped; no remote reset exists. Temporary reports genuinely age/expire rather than being silently renewed for a presentation. Retain labelled rehearsal entries and reuse their detail; do not clean out another person's records. The ignored demo manifest contains a guest session and must stay private.

Android emulator evidence does not prove physical-phone/iOS behaviour, spoken TalkBack/VoiceOver ordering, release performance, FPS, memory or production scaling. The five-minute schedule is proposed; an actual presenter must rehearse it on the judging device/network. See the current phase results and final defect inventory for measured checks and remaining manual gates. Do not describe this MVP as production-ready.

Dependency audit remains open (65 propagated records in the working install; no critical advisory, but high/moderate findings). Expo suggests two patch updates; audit-fix dry run fails peer resolution. See [security review](phase14/security-review.md) for affected paths and risks, including malformed deep-link availability. No forced SDK upgrade or clean-audit claim. Expo Go can need a cold relaunch when switching between development servers; prewarm only the presentation project. Brief future timestamps may show unknown until the 30-second refresh.
